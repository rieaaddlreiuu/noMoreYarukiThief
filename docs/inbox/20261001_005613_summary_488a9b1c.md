# セッション要約：Discord Botを別サーバーで使う設定

## 背景・経緯
- Discord Bot（no more やる気泥棒）を、最初に登録したサーバー以外でも使いたい。
- `DISCORD_GUILD_ID` を変えて `npm run discord:register` を実行し、Vercelの環境変数も変えたが、新しいサーバーで `/niki` が出なかった。
- 最終的にコマンドをグローバル登録にしたところ、ギルド登録のコマンドと重複して表示された。

## 開発者に説明したこと・理解してもらったこと
- **ギルドコマンド**（特定サーバー限定のコマンド）は、追加されるだけで上書きされない。サーバーIDを変えて登録すると、古いサーバーの登録も残る。
- **`DISCORD_GUILD_ID` を読むのは登録スクリプトだけ**で、アプリ本体（Vercel上）は読まない。そのためVercel側で変えても効果はない。登録は `.env.local` を使ってローカルで行う。
- 新サーバーで `/niki` が出なかった原因は、**Discordクライアントのキャッシュ**だった。`Ctrl+R` で再読み込みして解決した。
- 招待したアプリと、コマンドを登録したアプリ（`DISCORD_APPLICATION_ID`）が別だと、コマンドが出ない。スクリーンショットでは「テスト」アプリと本番アプリが両方入っていた。
- **グローバル登録にすれば**、コードや環境変数を変えずに新サーバーへ導入できる。新サーバーごとに必要な作業は次の3つ。
  1. Botを招待する
  2. サーバー管理者が `/niki setup channel:#通知先` を実行する
  3. 各メンバーがGitHub連携をする
- 他人のサーバーにも入れる場合は、Developer PortalでBotを「Public Bot」にする必要がある。

## 決定事項
- コマンドは**グローバル登録**で運用する（`DISCORD_GUILD_ID` は空にする）。
- 重複していたギルドスコープの `/niki` は削除する。

## 実施したこと
- Discord APIで、次の2つのサーバーのギルドスコープ `/niki` を削除した（どちらも HTTP 204）。
  - 1531548311830659092
  - 1552121860462874694
- グローバルコマンドには触れていない。

## 変更したファイル
- コードやファイルの変更はなし（このまとめの追加のみ）。
- 変更したのはDiscord上の登録データ（ギルドコマンドの削除）のみ。

## 次にやること
- `.env.local` の `DISCORD_GUILD_ID` を空にする（次回の登録もグローバルだけにするため）。
- Discordを `Ctrl+R` で再読み込みし、`/niki` の重複が消えたか確認する。
- 新サーバーで `/niki setup channel:#通知先` を実行する。
- 招待するアプリと `DISCORD_APPLICATION_ID` が同じか確認する。別アプリは外す。
- 他人のサーバーにも入れるなら、Developer Portalで「Public Bot」をオンにする。
- 補足：`.env.prduction` はファイル名が `production` のtypoになっている。
