# セッション要約：Discord Botの動かし方とechoボットの追加

## 背景・経緯
- プロジェクトは「開発ニキ」（noMoreYarukiThief）。開発宣言・GitHubでのコミット確認・Discordでの声かけを行うBot。
- 開発者から「Discord Botの動かし方」「localhostで動かしたい」という質問があり、説明した。
- その後「アプリの機能ではなく、誰かの投稿に反応してechoする（オウム返しする）Botをまず作りたい」という依頼があり、計画（プラン）を立てて実装した。

## 開発者に説明したこと・理解してもらったこと
- 既存のBotは **HTTP Interactions方式**（Discordがスラッシュコマンドを当方のURLに送ってくる仕組み）で、常駐プロセスを持たない。期限判定はSupabase Cron（定期実行機能）が担当する。
- localhostで既存Botを試すには、ngrok / cloudflared などの「トンネル」（手元のPCを一時的にインターネット公開するツール）でHTTPS URLを作る必要がある。`APP_URL`、DiscordのEndpoint URL、GitHubのCallback URLにそのURLを設定する。Cronはlocalhostに届かないので、評価APIを手動で呼ぶ。
- **通常の投稿への反応にはHTTP方式では足りず、Gateway接続**（BotがDiscordに常時つないで投稿を受け取る方式）が必要。そのため、既存アプリとは別の常駐スクリプトとして作った。Gateway方式はトンネル不要でlocalhostのまま動く。
- 通常の投稿の中身を読むには、Developer Portalで **Message Content Intent**（メッセージ本文を読む許可）をONにする必要がある。

## 決定事項
- 反応方式は **Gateway常駐Bot**（discord.js使用）。
- 対象は **特定チャンネルのみ**（環境変数 `ECHO_CHANNEL_ID` で指定）。暴走や他チャンネルへの誤爆を防ぐため。
- Bot自身の投稿と空の投稿には反応しない（無限ループ防止）。メンションは無効化（`@everyone` 誤爆防止）。
- 既存のNext.jsコード・DB・Cronには触れない。

## 次にやること
1. Developer Portal → Bot → **Message Content Intent をON**にする。
2. `.env.local` に `DISCORD_BOT_TOKEN` と `ECHO_CHANNEL_ID`（チャンネルを右クリック→IDをコピー。開発者モードが必要）を設定する。
3. Botがそのチャンネルを見て、メッセージを送れる権限を持っているか確認する。
4. `npm run echo` を実行し、`ready: ...` の表示を確認する。
5. 指定チャンネルに投稿してオウム返しされるか、別チャンネルやBot投稿には反応しないかを確認する。
6. 動作確認後、本来の「開発ニキ」機能の動作確認（トンネル経由）に進む。
