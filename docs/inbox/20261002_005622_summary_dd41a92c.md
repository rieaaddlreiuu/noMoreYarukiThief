# セッション要約: GitHubトークンの取得と、ユーザートークンの暗号化保存

## 背景・経緯
- 最初の質問は「GitHub APIの認証トークンの取得方法」。
- 次に「それはデベロッパー設定の中のアプリ設定か」と質問があった。
- 最後に「他のユーザーのGitHubにアクセスできるようにしたい」という要望があった。
- 調査の結果、このプロジェクト(Discordボット)にはすでに **GitHub OAuth App**(ユーザーがGitHubアカウントを連携する仕組み)がある。
  - ただし連携後にユーザーのトークンを捨てていたため、そのユーザー自身の権限でGitHubを呼べなかった。
  - コミット確認は、運営側の1つのトークン(`GITHUB_API_TOKEN`)だけで行っていた。

## 開発者に説明したこと
- **トークンの取得手順**: GitHubの Settings → Developer settings → Personal access tokens(Fine-grained 推奨)。
- **Developer settings の3種類の違い**
  - Personal access token: 自分のアカウントとしてAPIを使う。
  - GitHub App / OAuth App: 他のユーザーの許可を得て、そのユーザーのデータを使う。
- **他のユーザーのデータを扱うにはOAuthが必要**で、このプロジェクトには既にOAuth Appがあること。
- **実装後の動作の論理確認**
  - 連携時: トークンを暗号化して保存する。
  - 確認時: そのユーザーのトークンで確認する。
  - トークンが無い、失効、復号失敗の場合は、運営側トークンに自動で切り替わる。

## 決定事項
- アクセス対象は **公開リポジトリのみ**(OAuthのスコープ = 権限の範囲は空のまま)。
- ユーザートークンは **暗号化(AES-256-GCM)してDBに保存する**。
  - 鍵は環境変数 `TOKEN_ENCRYPTION_KEY` で渡す。
  - 未設定の場合はトークンを保存せず、従来どおり動く。
- 保存したトークンは、そのユーザーの宣言のコミット確認に使い、レート制限(API呼び出し回数の上限)をユーザーごとに分散させる。
- 非公開リポジトリが必要になった場合は、GitHub App への移行を検討する。
