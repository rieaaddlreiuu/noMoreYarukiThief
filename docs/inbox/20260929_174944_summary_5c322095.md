# セッション要約: `/niki` コマンドが動かない不具合の調査

## 背景・経緯

開発者（非エンジニア）が `docs/setup.md` の手順に従い、Discordサーバーへ `/niki` コマンドを登録するところまでは完了した。しかし実際に `/niki github`・`/niki status`・`/niki setup` などどのコマンドを打っても、Discord上で

> 処理を完了できませんでした。/niki status で保存状況を確認し、時間をおいて再実行してください。

という汎用エラーメッセージが毎回返ってくる状態だった。

## 開発者に説明したこと・理解してもらったこと

- このエラーメッセージは、想定内の個別エラー（例: 「先にGitHub連携してください」など）ではなく、**予期しない例外**が発生したときに返る「なんでも受け皿」のメッセージであること（`src/lib/discord/handler.ts` の `commandErrorMessage` 関数）。
- セキュリティ上の理由で、DB（Supabase）関連のエラーは詳細を隠す設計になっており（`src/lib/security.ts` の `safeError` 関数）、Vercelのログを見ても「Processing failed」としか出ず、詳細な原因はログからは分からない設計になっている。
- **Botのメンバー一覧での「オフライン」表示は問題ない**こと。このBotは常時接続（Discordの用語で「Gateway」）を使わず、Discord側から必要なときだけHTTPで呼び出される方式（Webhook形式）で動くため、オンライン表示にはならない仕様（`docs/setup.md` 4-1章に明記）。他の人のBotがオンラインに見えるのは、そちらが別方式（常時接続）で作られているため。
- `/niki setup` を含め**どのコマンドを打っても同じ汎用エラーになる**ことから、コマンドごとの個別処理ではなく、**全コマンド共通の最初の処理**（Supabase＝データベースへの接続・書き込み）で失敗している可能性が高いと切り分けた。
- 切り分けの過程で、Supabaseの管理画面（Table Editor）で `interaction_receipts` というテーブルを見てもらい、コマンドを打っても行が増えていないことを確認 → データベースへの書き込み自体が届いていないと判明。

## 決定事項（原因の特定）

Supabaseダッシュボードの「Integrations → Data API」画面に表示されていたAPI URLが

```
https://peykcxorqfwjujmlgytw.supabase.co/rest/v1/
```

だった。これは末尾に `/rest/v1/` が付いた「REST APIのエンドポイントURL」であり、プログラム内で使う `SUPABASE_URL`（Supabaseライブラリが内部で自動的に `/rest/v1` などのパスを追加する前提の、**末尾に何も付かないプロジェクトの基点URL**）とは別物。

もし開発者がこの `/rest/v1/` 付きのURLをそのまま環境変数 `SUPABASE_URL` に設定していた場合、実際のアクセス先が `.../rest/v1/rest/v1/...` という**存在しないパス**になってしまい、データベースへのアクセスが全滅する。これは「全コマンドが同じエラーで失敗する」「テーブルに行が増えない」という観察結果とすべて一致する。

**対処方法として案内した内容**:

- `SUPABASE_URL` を、末尾のスラッシュや `rest/v1` を含まない下記の値に修正する。

  ```
  https://peykcxorqfwjujmlgytw.supabase.co
  ```

- 正しい値は、Supabaseダッシュボードの「Project Settings → API」の「Project URL」欄（今回見ていた「Integrations → Data API」画面ではない）で確認できる。
- Vercel側の環境変数を修正した後、**キャッシュなしで再度Redeploy**する（環境変数は既存デプロイには自動反映されないため。`docs/setup.md` 4-2章参照）。

**注**: このセッション終了時点で、開発者が実際に `SUPABASE_URL` を修正し再デプロイして動作確認するところまでは至っていない（次回への持ち越し）。

## 次にやること

1. Vercelの環境変数 `SUPABASE_URL` を `https://peykcxorqfwjujmlgytw.supabase.co`（末尾に `/rest/v1/` を付けない）に修正する。
2. Vercelでキャッシュなしの Redeploy を実行する。
3. 再度 `/niki setup channel:...` → `/niki github` → `/niki status` を試し、Supabaseの `interaction_receipts` テーブルに行が増えるか、正常なメッセージが返るかを確認する。
4. もしこれでも直らない場合は、`SUPABASE_SERVICE_ROLE_KEY` の値（`anon` キーと取り違えていないか、コピペ時に余分な空白・改行が入っていないか）を改めて確認する。
